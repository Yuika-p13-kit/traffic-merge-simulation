# Highway merge v3 — Step 4 事前評価レポート

## 目的

`highway_merge_v3` に対し、信号・停止線・主線の完全停止を使わない協調合流を実装する。ランプ待ち車両が発生したときだけ、合流区間へ到達する主線車両へ一時的な速度助言を与え、ランプ車両が安全に車線変更できるギャップを作る。

旧 `minimal_merge` 用のStep 4-1/4-2は、1車線のpriority junctionを対象にした結果であり、主線2車線・600 mの並走合流区間・下流2車線を持つv3には移植しない。

## 基準条件

Step 3で制御比較の第一候補とした以下を固定する。

- 総需要: 3,950 veh/h
- 主線:ランプ: 1:2（主線1,317 veh/h、ランプ2,633 veh/h）
- seed: 7 / 42 / 99 / 123 / 2026
- 需要投入: 1,800秒、クリアランス: 600秒

無制御は5/5 seedでbreakdownし、平均未完了台数257.6台、平均処理量3,436.8 veh/hだった。v3固有の基準値として以後の比較に使う。

## 初期方式と評価基準

初期実装では、ランプ合流端に近く一定時間待機する車両を検知する。合流端の上流にいて到着時刻が競合する主線車両だけを対象にし、速度助言を一定時間で解除する。対象ランプ車両の合流、タイムアウト、または対象車両の退出後はクールダウンへ移る。

各改善は、事前にこのレポートと対応するQiita原稿へ仮説・比較条件・判定基準を追記してから実装する。実装直前には、その文書変更をコミットする。

Step 4の達成判定は、代表条件で以下をすべて満たすこととする。

1. 無制御の平均未完了台数257.6台を下回る。
2. 無制御の平均処理量3,436.8 veh/hを上回る。
3. 5 seed中3 seed以上がクリアランス内に回復する。
4. 衝突・テレポートを発生させない。

最初の方式が未達なら、結果を保存・報告し、失敗要因と次の仮説を文書化してコミットしてから次の限定的な改善を行う。

## 初期仮説

ランプ車両が過多な代表条件では、並走区間末端付近で主線車両との到着競合が繰り返されると考える。全主線車両を減速させるのではなく、合流端まで数秒の主線車両だけを緩やかに減速させれば、主線2車線の流れを保ちながらランプ側の合流機会を増やせる可能性がある。

## 初期方式の結果

初期方式を上記の5 seedで実行した。無制御・協調制御ともに、平均未完了台数257.6台、平均処理量3,436.8 veh/h、回復0/5、衝突・テレポート0だった。協調制御の平均介入回数は0回であり、4つの達成条件のうち安全性だけを満たした。

原因は、ランプ上流で入路待ちが発生している一方、`main_merge_0`を走行するランプ車両の停止待ち時間がほぼ0秒だったことにある。初期方式が「並走区間内で3秒以上停止する車両」を起動条件にしたため、制御が一度も開始されなかった。

## 改善1の仮説と事前判定

改善1では、停止待ち時間を起動条件から除き、ランプ専用レーンの終端から180 m以内を走行する車両があるときにだけ競合を判定する。主線側の対象レーン、速度助言、最大介入時間、クールダウン、比較条件、達成条件は変えない。

これにより、停止する前のランプ車両に対して合流ギャップを準備できる。平均介入回数が正となり、無制御より未完了台数と処理量の少なくとも一方が改善することを、次の実測で確認する。
