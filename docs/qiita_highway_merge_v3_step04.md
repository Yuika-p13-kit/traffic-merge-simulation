# 【SUMO】2車線合流モデルで協調合流を検証する（Step 4・着手前）

## はじめに

前回までに、主線上流2車線、ランプ1車線、600 mの3車線並走区間、下流2車線からなる `highway_merge_v3` を評価した。総需要3,950 veh/h・主線:ランプ=1:2では、5つの乱数seedすべてで需要終了後も車両が残った。今回は、この条件に対して協調合流を検証する。

## 旧モデルの結果を流用しない理由

以前の協調合流は、2流入1流出のpriority junctionで、主線1車線へ速度助言を出す方式だった。v3には2本の主線車線と600 mの並走区間があるため、同じ数値や結論を流用すると道路構造の違いを見落とす。そこで、v3の無制御結果だけを基準に新しいStep 4を始める。

## 比較条件と成功条件

比較条件は総需要3,950 veh/h、主線:ランプ=1:2、seed 7 / 42 / 99 / 123 / 2026、需要投入1,800秒、クリアランス600秒とする。無制御の平均未完了台数は257.6台、平均処理量は3,436.8 veh/hだった。

協調制御は、ランプ側で待機が発生したときだけ、合流端へ数秒で到達する主線車両に緩やかな速度助言を出す。信号、停止線、主線の完全停止は使わない。対象ランプ車両の合流または制限時間で助言を解除し、連続介入を防ぐためのクールダウンを置く。

成功は、平均未完了台数の削減、平均処理量の増加、5 seed中3 seed以上の回復、衝突・テレポートなしの4条件を同時に満たすことと定義する。次回は初期方式の実装と実測結果を示す。

## 初期実装で分かったこと

初期方式を5 seedで実行したところ、協調制御の介入回数は0回だった。未完了台数257.6台、処理量3,436.8 veh/h、回復0/5はいずれも無制御と同じで、衝突とテレポートはなかった。

原因は、ランプ需要の超過が並走区間内の停止ではなく、ランプ上流での流入待ちとして表れたためである。並走区間のランプ車両は停止する前に走行しており、「3秒以上待った車両」という起動条件には該当しなかった。

次の改善では、停止待ち時間を待たず、ランプ専用レーンの終端へ近づいた車両を検知する。主線への助言は引き続き競合車両だけに限定し、同じ5 seedで比較する。
