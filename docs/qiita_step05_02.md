# 道路に入れない車両も渋滞である——SUMOの挿入待ちをTTSへ加えた

## はじめに

前回のStep 5-1では、シミュレーション終了時に道路上へ残る車両も含めてTotal Time Spent（TTS）を計測した。到着車両だけを使う平均旅行時間より、公平に戦略を比較できるようになったはずだった。

しかし結果を照合すると、SUMOがロードした車両数と、実際に道路へ出発した車両数が一致しない条件があった。予定出発時刻を過ぎても流入エッジに空きがなく、道路の外で挿入待ちになっている車両である。

Step 5-1のTTSは道路上の未到着車両を含むが、道路へ入ることすらできない車両を含まない。そこでStep 5-2では、挿入待ち時間をTTSへ追加した。すると、協調制御の改善も悪化も、Step 5-1で見えていた差より大きいことが分かった。

## 完全版TTSの定義

SUMOのTraCIには `simulation.getPendingVehicles()` がある。これは、予定出発時刻を過ぎても道路へ挿入できない車両IDを返す。

各ステップで道路内車両と挿入待ち車両を別々に数え、時間積分した。

```text
道路内TTS = Σ（道路内車両数 × ステップ長）
挿入待ちTTS = Σ（挿入待ち車両数 × ステップ長）
完全版TTS = 道路内TTS + 挿入待ちTTS
```

主線・サブ別にも同じ値を記録する。

## 実験条件

| 項目 | 条件 |
|---|---|
| 総需要 | 800 / 1,000 / 1,200 veh/h |
| 主線:サブ | 1:1〜1:5 |
| 戦略 | 無制御 / 限定協調制御 |
| seed | 1〜5 |
| 需要投入 | 1,800秒 |
| クリアランス | 600秒 |
| 合計 | 150ラン |

制御設定はStep 4-2、評価条件はStep 5-1から変更していない。

## 本当に全車両を数えられたか

TraCIでロードされた車両IDを累積し、SUMO summaryの最終ロード台数と照合した。全150ランで差は0台だった。

さらに、次の関係も全ランで一致した。

- 完全版TTS = 道路内TTS + 挿入待ちTTS
- 全体TTS = 主線TTS + サブTTS
- 全体未到着 = 主線未到着 + サブ未到着
- Step 5-1のTTS = Step 5-2の道路内TTS

挿入待ちは150ラン中120ランで発生し、69ランでは終了時にも車両が挿入待ちのまま残っていた。

## 結果

| 条件 | 無制御TTS | 協調TTS | 変化 |
|---:|---:|---:|---:|
| 800・1:2 | 197,109.8秒 | 193,864.6秒 | -1.6% |
| 1,000・1:3 | 340,020.4秒 | 330,795.4秒 | -2.7% |
| 1,200・1:2 | 466,884.8秒 | 464,101.8秒 | -0.6% |
| 1,200・1:3 | 494,981.6秒 | 490,892.6秒 | -0.8% |
| 800・1:3 | 115,815.8秒 | 177,367.6秒 | +53.1% |
| 1,000・1:4 | 243,737.0秒 | 323,901.8秒 | +32.9% |
| 1,200・1:5 | 397,141.6秒 | 480,082.2秒 | +20.9% |

## 1,000 veh/h・1:3の改善は道路外にあった

この条件では、完全版TTSが9,225秒、2.7%改善した。

内訳を見ると、道路内TTSの改善は208秒だけだった。一方、挿入待ちTTSは9,017秒改善していた。改善の約98%が、サブ車両を道路へ早く入れられた効果だった。

Step 5-1で見えていた改善は0.2%だった。道路内だけを観測すると、制御の主な効果を取りこぼすことになる。

ただし、TTSが改善したのは5 seed中3 seedである。同一seed差の95%信頼区間もゼロを含むため、安定した優位性が確認できたわけではない。

## 悪化も道路外で拡大した

800・1:3、1,000・1:4、1,200・1:5は全seedで悪化した。

1,000・1:4では、道路内TTSは6,782秒の悪化だったが、挿入待ちTTSは73,383秒悪化した。道路内だけを見ていたStep 5-1は、総損失の大部分を見落としていた。

この3条件は、同一seed差の95%信頼区間もすべて悪化側にある。単一の協調制御設定を全需要条件へ適用してはいけない。

## 挿入待ちは100%サブ側だった

主線の挿入待ちTTSは全150ランで0秒だった。挿入待ちによる損失はすべてサブ側に発生している。

これは主線優先合流というモデルの構造をそのまま表している。高需要時には、サブ側の道路外待ちが道路上の滞在時間より大きくなる条件もあった。

合流部の評価でネットワーク内だけを見ると、従線の負担を過小評価する。シミュレーション対象の境界外で待っている車両も、交通需要としては消えていない。

## breakdownは解消しなかった

完全版TTSが改善した条件はあるが、無制御のbreakdownを協調制御でqueueへ移したランは0だった。逆にqueueからbreakdownへ悪化したランが6あった。

限定速度助言は一部条件の損失を減らせても、容量不足を解消する制御にはなっていない。

## 次に必要な可視化

現在のグラフは戦略ごとの平均絶対値を表示している。これだけでは、同一seedでどれだけ変化したか、seed間変動に対して平均差が大きいかを判断しにくい。

Step 5-3では、次を追加する。

- 同一seedの `協調制御 - 無制御` 差
- 平均差
- 平均差の95%信頼区間
- 信頼区間がゼロをまたぐかどうか

改善候補と明確な悪化条件を、同じ基準で図から判断できるようにする。

## まとめ

- 道路内TTSへ挿入待ちTTSを加えた
- 全150ランでロード車両数とTTS内訳の整合性を確認した
- 挿入待ちは120ランで発生した
- 挿入待ち損失は100%サブ側だった
- 1,000 veh/h・1:3の改善の約98%は挿入待ちの減少だった
- 3条件では全seedでTTSが大幅に悪化した
- 協調制御でbreakdownを解消したランはなかった

道路の外で待っているからといって、その車両を評価から外してよいわけではない。シミュレーション境界を越えて、需要として投入した全車両を数える必要がある。
