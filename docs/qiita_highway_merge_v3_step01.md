# SUMOで高速道路型の合流を組み直す——まずは無制御ベースラインを確認した

## はじめに

合流制御を比べる前に、制御を入れない道路がどの程度まで自然に流れるかを確認する必要がある。本稿では、Eclipse SUMOで作り直した高速道路型合流モデル `highway_merge_v3` の最初の無制御ベースラインを示す。

以前の単純な合流モデルとは道路構造が異なるため、過去の数値を引き継がない。v3では主線2車線、ランプ、600 mの合流区間、下流2車線を明示し、以後の需要較正と制御評価をこのネットワークだけで行う。

## モデル

- 主線上流: 2車線
- 合流区間: 3車線（主線2車線とランプ1車線）、600 m
- 下流: 2車線
- 制御: なし
- シミュレータ: Eclipse SUMO
- 実行・集計: Python

ランプは合流区間の始点で加わり、その車線だけが区間終端で消える。実在JCTの完全再現ではなく、主従関係を持つ高速道路合流の構造を検証するためのモデルである。

## 実験条件

主線需要とランプ需要を小さな格子で変え、まず低〜中需要域で流出完了とシミュレーションの健全性を確かめた。

| 項目 | 条件 |
|---|---|
| 主線需要 | 600 / 1,200 / 1,800 veh/h |
| ランプ需要 | 200 / 600 / 1,000 veh/h |
| seed | 7 / 42 / 99 |
| 需要投入 | 120秒 |
| クリアランス | 180秒 |
| 制御 | なし |

確認したのは、クリアランス終了時の未完了車両、衝突、テレポート、ピーク停止車両数、待ち時間、処理量である。

## 結果

9需要条件、各3 seedの計27実行で、すべての車両がクリアランス内に到着した。衝突・テレポートも0件で、ピーク停止車両数と平均待ち時間はいずれも0だった。

| 主線 (veh/h) | ランプ (veh/h) | 流出完了 | 衝突 | テレポート | 平均ピーク停止 |
|---:|---:|---:|---:|---:|---:|
| 600 | 200 / 600 / 1,000 | 3/3 | 0 | 0 | 0.0 |
| 1,200 | 200 / 600 / 1,000 | 3/3 | 0 | 0 | 0.0 |
| 1,800 | 200 / 600 / 1,000 | 3/3 | 0 | 0 | 0.0 |

この範囲では、主線1,800 veh/hとランプ1,000 veh/hを同時に与えても、無制御で停止待ち行列を生じずに処理できた。

## 次の実験へ

Step 1は容量そのものを測る実験ではない。次のStep 2では、無停止を確認できた主線1,800 veh/hを固定し、ランプ需要を増やして「需要停止後も回復できるか」の境界を探す。

## 再現方法

```bash
PYTHONPATH=src uv run python experiments/highway_merge_v3/step01_baseline/run.py
```

生データ、集約CSV、実験条件は `experiments/highway_merge_v3/step01_baseline/results/` に保存される。

## 注意点

- 120秒の短い需要投入による初期較正であり、長時間の容量評価ではない
- 結果はこのネットワーク形状、車両モデル、seed集合に限られる
- 実道路の交通量や車種構成を再現したものではない

次回は、同じv3ネットワークでランプ需要を広く振り、無制御合流の回復可能な境界を測定する。
