# 総交通量が同じでも合流は崩れる——SUMOで主線・ランプの需要比を変えてみた

## はじめに

高速道路の合流で混雑を考えるとき、合流部へ到着する総交通量に注目しがちである。しかし、同じ総交通量でも、主線とランプのどちらから何台来るかで、無制御合流は変わるのだろうか。

Eclipse SUMOの `highway_merge_v3` を使い、総需要を固定して主線:ランプの需要比だけを変えた。結果は明快だった。総需要3,950 / 4,000 veh/hでは、1:1は全seedで回復したのに対し、ランプ需要が2倍以上の1:2〜1:5はすべてのseedで回復しなかった。

## モデルと判定

モデルは主線上流2車線、ランプ、600 mの3車線合流区間、下流2車線で構成する。信号、Ramp Metering、協調制御は加えていない。

Step 2で得た境界付近を調べるため、需要を1,800秒投入した後、600秒のクリアランスを設けた。終了時に未完了車両が1台でも残れば `breakdown`、全車両が到着すれば `recovered` とした。停止の有無だけでは判定しない。

| 項目 | 条件 |
|---|---|
| 総需要 | 3,950 / 4,000 veh/h |
| 需要比（主線:ランプ） | 1:1 / 1:2 / 1:3 / 1:4 / 1:5 |
| seed | 7 / 42 / 99 / 123 / 2026 |
| 需要投入 | 1,800秒 |
| クリアランス | 600秒 |
| 制御 | なし |

たとえば総需要3,950 veh/h・1:2は、主線1,317 veh/h、ランプ2,633 veh/hに配分する。

## 同じ総需要でも、配分で回復可否が変わった

総需要3,950 veh/hは、Step 2で求めた4,000 veh/hの破綻境界よりわずかに低い。それでも、1:1では全seedで回復する一方、1:2では全seedで破綻した。つまり、総量だけでは回復可否を説明できない。

ランプ比率を増やすほど、平均未完了台数は257.6台から582.4台へ増え、平均処理量は3,436.8 veh/hから2,787.2 veh/hへ低下した。4,000 veh/hでも同じ順序が再現された。

このモデルでは、ランプ車両が合流区間の終端までに主線の2車線へ移らなければならない。ランプ需要の偏りが大きいほど、その車線変更と合流が集中し、下流2車線へ流れ出す過程が詰まりやすくなると考えられる。これはシミュレーション結果からの解釈であり、実道路一般への直接の一般化ではない。

## 次の制御比較に何を使うか

最初の制御比較の代表条件は、総需要3,950 veh/h・需要比1:2とする。境界よりわずかに低い需要であるにもかかわらず、無制御では5/5で破綻する。一方で1:3〜1:5より未完了台数が少なく、改善が起きた場合に差を読み取りやすい。総需要4,000 veh/h・1:2は、境界直上での頑健性確認用に残す。

重要なのは、「ランプを優遇する制御が必ず有効」とはまだ言えないことだ。次の段階では、主線とランプのどちらかへ負担を押し付けるだけにならないよう、未完了車両に加えて道路全体の時間損失を評価する必要がある。

## 再現方法

```bash
PYTHONPATH=src uv run python experiments/highway_merge_v3/step03_demand_ratio/run.py
```

生データ、集約CSV、実験条件は `experiments/highway_merge_v3/step03_demand_ratio/results/` に保存される。

## 限界

- 結論はv3の道路形状、車両モデル、周期的到着、実験時間、seed集合に限られる
- seedは5個であり、破綻確率の精密な推定には追加実験が必要
- 到着済み車両の平均停止時間には、道路へ入れずに待つ損失を含めない
- 実道路の容量や、特定JCTでの制御効果を直接示すものではない

## まとめ

- v3高速道路型合流では、総需要3,950 / 4,000 veh/hで1:1は全seed回復した
- 同じ総需要でも1:2〜1:5は全seedで破綻した
- ランプ比率が高いほど未完了車両が増え、処理量が低下した
- 次の制御比較は3,950 veh/h・1:2を主条件として始める
