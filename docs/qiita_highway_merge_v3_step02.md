# SUMOで高速道路合流の回復限界を測る——5 seedで見えた4,000 veh/h付近の境界

## はじめに

前回は、主線2車線・ランプ・下流2車線からなる `highway_merge_v3` で、低〜中需要域の無制御ベースラインを確認した。今回は主線需要を固定してランプ需要を増やし、需要投入を止めた後に回復できる境界を測る。

ここで得る値は普遍的な道路容量ではない。ネットワーク、車両モデル、需要時間、seed、そして回復を待つ時間に依存する「今回の運用条件での境界」である。

## 判定の考え方

需要を止める時刻とシミュレーションを終える時刻を分けた。投入終了直前の車両が単に走り終わる時間を持たなかっただけで破綻と判定されるのを避けるためである。

```text
0秒                    1,800秒                 2,400秒
|------ 需要を投入 ------|------ 回復を観測 ------|
                         <--- 600秒 --->
```

- `recovered`: クリアランス終了までに、読み込まれた全車両が到着した
- `breakdown`: クリアランス終了時に未完了車両が1台以上残った

車線変更中の短時間停止だけでは `breakdown` としない。各条件を5 seedで実行し、多数決で集約した。同数なら安全側の `breakdown` を採用した。

## 実験条件

| 項目 | 条件 |
|---|---:|
| 主線需要 | 1,800 veh/h（Step 1で無停止を確認） |
| ランプ需要（広域） | 0〜3,600 veh/h、400刻み |
| ランプ需要（絞り込み） | 2,000〜2,400 veh/h、50刻み |
| seed | 7 / 42 / 99 / 123 / 2026 |
| 需要投入 | 1,800秒 |
| クリアランス | 600秒 |

絞り込み実験は、ランプから加速車線へ入る内部接続の速度上限を22.34 m/sへ修正したネットワークで再実行した。

## 結果

広域探索では、ランプ2,000 veh/hが5/5で `recovered`、2,400 veh/hが5/5で `breakdown` となった。そこでこの間を50 veh/h刻みで再測定した。

| 主線 (veh/h) | ランプ (veh/h) | recovered | breakdown | 判定 | 平均未完了台数 |
|---:|---:|---:|---:|---|---:|
| 1,800 | 2,100 | 5/5 | 0/5 | recovered | 0.0 |
| 1,800 | 2,150 | 4/5 | 1/5 | recovered | 4.2 |
| 1,800 | 2,200 | 0/5 | 5/5 | breakdown | 30.4 |

したがって、今回の条件での最初の多数決破綻点は、主線1,800 veh/hとランプ2,200 veh/h、合計4,000 veh/hだった。広域と絞り込みを合わせた95実行で、衝突・テレポートはいずれも0件である。

## 読み方

2,150 veh/hでは1 seedだけ未完了車両が残ったが、多数決では回復側に分類された。境界は一本の決定的な線ではなく、seedによって揺れる遷移域として現れている。

また、4,000 veh/hは「道路の真の容量」ではない。600秒で回復するかを問う実験上の判定点であり、クリアランス時間や到着パターンを変えれば位置も変わりうる。

## 次の実験

Step 3では総需要を3,950 / 4,000 veh/h付近に固定し、主線:ランプの需要比を変える。同じ総需要でも配分によって回復・破綻が変わるかを確認する。

## 再現方法

```bash
PYTHONPATH=src uv run python experiments/highway_merge_v3/step02_throughput/run.py
```

広域結果、絞り込み結果、実験条件は `experiments/highway_merge_v3/step02_throughput/results/` に保存される。

## 限界

- 主線需要は1,800 veh/hの1条件だけを固定した
- seedは5個で、破綻確率を精密に推定するには不足している
- 周期的な車両発生を用いており、ランダム到着の頑健性は未検証
- 実道路の容量値として使うことはできない
