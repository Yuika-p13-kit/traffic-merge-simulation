# Step 2: 交通量・容量スイープ

主線・従線需要を変化させ、待ち行列と容量限界を確認する。需要投入終了後にクリアランス時間を設け、終了直前に流入した車両を渋滞と誤判定しない。

```bash
uv run python experiments/step02_throughput/run.py
```

既定では `main=200 veh/h`、side側を0〜1,000 veh/h（境界付近は1〜5刻み）、5 seed、需要投入1,800秒、クリアランス600秒で調べる。

- `free_flow`: 投入中に停止・挿入待ちがなく、クリアランス後の未到着もない
- `queue`: 投入中に停止・挿入待ちが生じるが、クリアランス中に解消する
- `breakdown`: クリアランス後も未到着車両が残る

seed間は多数決で集約し、同数の場合は重い状態を採用する。生データ、集約結果、metadataは `results/` に保存する。

現時点の結果と解釈は `RESULTS.md` を参照する。

## 終了条件

- 終了直前の正常走行車両を渋滞扱いしない判定になっている
- 複数seedで `main=200 veh/h` の queue / breakdown 境界を特定している
- 生データ、集約結果、条件、判定定義から結果を再現できる
- 実行コードのテストが成功している

主線交通量全域への一般化は、固定制御の開始を妨げないため、このステップの終了条件には含めない。

- 最初の比較では境界付近を優先し、広域の二次元スイープは比較実装後に行う
